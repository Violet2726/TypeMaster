# 需求池

## 需求管理说明

1. 需求按优先级分为 P0 / P1 / P2 三级
2. P0 需求应在近期迭代中完成
3. P1 需求根据资源情况安排
4. P2 需求作为未来规划

## 迭代规则

- 每个迭代周期从周一到周五
- 每周从 backlog 中选取 2-3 个高优先级任务
- 周五进行迭代回顾和下周期规划
- 新发现的需求、bug、技术债应随时加入 backlog 并标注优先级
