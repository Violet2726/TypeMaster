- **风险**: 新增状态时容易堆叠；测试困难

## 4. 下周最多三个重构主题

### 主题 A: 性能优化：减少首屏加载时间

#### 目标
优化 bundle 大小和加载策略，提升首屏加载速度。

#### 涉及模块
- `vite.config.js`
- `src/` 各模块（分析依赖）

#### 为什么必须重构
- 首屏加载时间较长，影响用户体验
- 已作为 today.md 任务连续几天待规划
- 现有 bundle 已拆分（react-vendor, router-vendor, main），但仍有优化空间

#### 旧逻辑清理范围
分析并优化：
- 依赖项（是否有未使用的依赖）
- 代码拆分（是否可进一步拆分包）
- Tree shaking（是否有未使用的代码）
- 压缩配置（是否可进一步优化）

#### 验收标准
- `npm run build` 成功
- bundle 大小至少减少 10%（从 330.59 kB 到 < 297 kB）
- `npm test` 全部通过（无回归）
- 所有页面功能正常（无 UI 或功能问题）

#### 风险
- 中风险：优化依赖可能导致功能问题
- 需要充分测试确保所有功能正常

#### 不做什么
- 不更换前端框架
- 不引入重大架构变更
- 不修改业务逻辑（仅优化加载）

## 6. 自动化测试补强建议

### 最能提升无人值守合并可靠性的测试

#### 优先级 1: 代码覆盖率监控（本周主题 B）
- **原因**: 知道测试覆盖情况有助于防止回归
- **预期收益**: 自动感知覆盖变化，提升测试质量
- **影响范围**: 所有测试模块

#### 优先级 2: 性能回归监控（长期）
- **原因**: 防止 bundle 大小和加载时间回归
- **方案**: 在 CI 中添加性能检查

### 测试策略原则

1. **engine 模块**: 纯函数优先，已有良好测试基线（117 tests）
2. **services 模块**: 依赖外部资源（localStorage/API），需要 mock，已有基线（storage + ai-service）
3. **store 模块**: 组合逻辑，可通过 engine + services 测试间接覆盖
4. **components 模块**: 渲染测试 ROI 低，优先保证下层测试
