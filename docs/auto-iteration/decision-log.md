### 2026-06-08 - 首页产品化为今日行动区

**决策类型**: 产品/体验

**决策内容**:
1. 首页不再只做状态汇总，升级为“今日行动区”
2. 首屏动作收敛为三条路径：推荐训练、每日挑战、自由练习
3. 每日挑战前置到首页一级入口，支持一键进入练习页

**决策理由**:
- 当前训练、挑战、自由练习能力都已存在，但入口分散
- 首页需要承担“下一步动作”而不是“信息陈列”的职责
- 先做信息架构升级，比立即推倒训练引擎更能提升主流产品感

**状态**: 生效中

### 2026-06-08 - 挑战结果页承担战绩反馈职责

**决策类型**: 产品/体验/技术

**决策内容**:
1. 每日挑战完成后，结果页必须直接展示挑战战绩
2. 名次、榜单合并、个人最佳判断抽成纯函数，而不是散落在页面内
3. 挑战完成时先做本地乐观更新，再异步同步 challenge 结果

**决策理由**:
- 仅有挑战入口而没有成绩反馈，会让留存激励在最后一步流失
- 榜单排序和个人最佳比较是可复用规则，应该被测试保护
- 乐观更新可以降低用户在结果页等待榜单同步的体感延迟

**状态**: 生效中

---

### 2026-06-08 - 挑战状态前置到入口层

**决策类型**: 产品/体验

**决策内容**:
1. 首页挑战卡必须直接展示今日挑战状态，而不只展示入口
2. ChallengePage 必须同时承担“个人战绩卡”和“同级别对比”职责
3. 完整榜单继续保留，但不再是用户理解自己位置的唯一入口

**决策理由**:
- 如果用户必须先完成挑战或深入榜单页才知道自己表现，回访动机过于滞后
- 主流产品会把“我的状态”放在入口附近，而不是藏在结果页深处
- 个人战绩与同级别位置是不同层次的反馈，应该并列呈现

**状态**: 生效中

### 2026-06-08 - 挑战页承担“我的战绩 + 同级别对比”双层反馈

**决策类型**: 产品/体验

**决策内容**:
1. ChallengePage 不再只做完整榜单页
2. 页面必须先展示“我的今日战绩”，再展示“同级别对比”，最后才是完整榜单
3. 首页挑战卡可以直接跳转到 ChallengePage 查看更完整反馈

**决策理由**:
- 用户真正关心的不是原始榜单本身，而是“我现在在哪里”
- 同级别位置能比全量排名更快帮助用户理解自己的竞争环境
- 首页需要一个承接页，而不是只把用户送去单一榜单表格

**状态**: 生效中

### 2026-06-08 - 挑战反馈要覆盖“当前状态 + 今日变化”

**决策类型**: 产品/体验

**决策内容**:
1. 首页挑战卡不能只展示静态排名，还要明确表达“今天是否刷新个人最佳”
2. ChallengePage 必须新增“今日挑战回放”模块
3. 回放默认围绕当日当前 challengeId 的尝试记录，不跨天合并

**决策理由**:
- 仅有名次不够回答“我刚才这一轮到底有没有进步”
- 用户继续挑战的主要依据是今天的波动过程，而不是全量历史
- 把当日变化说清楚，比单纯堆更多榜单信息更能驱动下一轮

**状态**: 生效中

### 2026-06-08 - 挑战历史默认围绕“今日当前挑战”

**决策类型**: 产品/体验/技术

**决策内容**:
1. ChallengePage 的历史回放只展示当前 daily challenge 的当日记录
2. 首页挑战卡的“个人最佳提示”优先围绕今日挑战样本判断
3. 不把跨天挑战记录混进同一个回放模块里

**决策理由**:
- 用户当前最关心的是“今天这几轮有没有变好”
- 跨天历史会稀释“再来一轮”的即时决策价值
- 先把当日口径打磨清楚，再决定是否扩展到更长时间跨度

**状态**: 生效中

### 2026-05-09 - jsdom→node 测试环境修复

**决策类型**: 技术/bugfix

**决策内容**:
1. 将 vitest.config.js 中测试环境从 jsdom 改为 node
2. jsdom 保留在 devDependencies 中备用

**决策理由**:
- jsdom v29.1.1 在 Node 18 CJS 环境下与 @exodus/bytes ESM 模块不兼容
- engine 模块的测试是纯 JS 逻辑，不需要 DOM 环境
- node 环境避免 ESM/CJS 兼容性问题

**状态**: 生效中
