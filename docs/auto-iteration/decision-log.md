### 2026-06-08 - 挑战焦点解释和主动作必须沉淀为共享模型

**决策类型**: 产品 / 体验 / 架构

**决策内容**:
1. 挑战单次焦点的文案映射不能继续散落在页面或组件内
2. 恢复状态判断统一由 training 层模型提供，而不是由 ResultPage 临时判断
3. 结果页主 CTA 使用模型输出的 `primaryAction` 和 `primaryLabel`
4. ChallengeTrendChart 只消费共享 focus note，不再维护自己的状态映射
5. training 层产品模型必须进入 Vitest 自动化测试范围

**决策理由**:
- 挑战反馈已经从展示型文案升级为可行动教练判断，需要有稳定的产品规则入口
- 页面层只应该展示和执行，不应该各自维护“什么状态该做什么”的规则
- 把模型放在 training 层，后续接入首页、移动端引导或更完整教练系统时更容易复用

**状态**: 生效中

### 2026-06-08 - 挑战结果页焦点反馈必须带下一步动作

**决策类型**: 产品 / 体验 / 规则

**决策内容**:
1. ResultPage 的挑战焦点反馈不能只解释本轮表现，还必须给出可点击的下一步动作
2. 健康或中性焦点状态下，主动作是“再挑战一次”，并直接启动 daily challenge
3. `accuracy-risk` 与 `speed-drop` 状态下，主动作必须从继续冲榜切换为恢复训练节奏
4. 如果存在活跃训练计划，恢复动作回到计划；否则回到自由热身
5. “查看榜单”保留为次级动作，避免排名反馈抢走训练节奏判断

**决策理由**:
- 主流训练产品不只解释结果，还会帮助用户做下一步选择
- 当系统已经识别出准确率风险或速度回落时，继续把冲榜作为主动作会伤害教练可信度
- 结果页是刚完成挑战后的最高意图触点，动作闭环应在这里完成，而不是要求用户再去别的页面理解建议

**状态**: 生效中

### 2026-06-08 - 挑战结果页必须给即时单次解释

**决策类型**: 产品 / 体验

**决策内容**:
1. ResultPage 的挑战战绩卡不仅展示榜单名次，也要展示当前回合的单次焦点判断
2. 当前回合解释复用 `getChallengePointFocusState`，不新增结果页专属规则
3. 如果存在上一轮挑战样本，结果页同步展示相对上次的速度和准确率变化
4. 榜单同步失败或 pending 时，单次解释仍可先展示，因为它来自本地 session 历史

**决策理由**:
- 用户刚完成挑战时，最需要立刻知道这轮训练意义
- 排名反馈依赖榜单同步，而单次解释可以本地即时给出
- 结果页是训练闭环的关键触点，不应该把“下一步怎么做”延后到 ChallengePage

**状态**: 生效中

### 2026-06-08 - 挑战趋势焦点必须给出可行动解释

**决策类型**: 产品 / 体验 / 规则

**决策内容**:
1. ChallengePage 的趋势图不能只展示 WPM 与准确率变化，还要解释单次挑战的训练意义
2. 单次焦点判断抽到 `getChallengePointFocusState`，由引擎层统一维护规则
3. 焦点说明默认落在最新一次挑战，让用户进入页面即可看到下一步动作判断
4. 焦点状态优先识别准确率风险和速度回落，避免只鼓励继续冲榜

**决策理由**:
- 用户复盘挑战时，最需要的是“这次表现说明什么”和“下一次怎么做”
- 单次变化比总体趋势更接近用户刚完成一次挑战后的决策场景
- 把规则放在引擎层，后续可以复用到结果页、首页和更完整的教练系统

**状态**: 生效中

### 2026-06-08 - 首页产品化为今日行动区

**决策类型**: 产品 / 体验

**决策内容**:
1. 首页不再只做状态汇总，升级为“今日行动区”
2. 首屏动作收敛为三条路径：推荐训练、每日挑战、自由练习
3. 每日挑战前置到首页一级入口，支持一键进入练习页

**决策理由**:
- 当前训练、挑战、自由练习能力都已存在，但入口分散
- 首页需要承担“下一步动作”而不是“信息陈列”的职责
- 先做信息架构升级，比立即推倒训练引擎更能提升主流产品感

**状态**: 生效中

### 2026-06-08 - 挑战结果页承担战绩反馈职责

**决策类型**: 产品 / 体验 / 技术

**决策内容**:
1. 每日挑战完成后，结果页必须直接展示挑战战绩
2. 名次、榜单合并、个人最佳判断抽成纯函数，而不是散落在页面内
3. 挑战完成时先做本地乐观更新，再异步同步 challenge 结果

**决策理由**:
- 仅有挑战入口而没有成绩反馈，会让留存激励在最后一步流失
- 榜单排序和个人最佳比较是可复用规则，应该被测试保护
- 乐观更新可以降低用户在结果页等待榜单同步的体感延迟

**状态**: 生效中

### 2026-06-08 - 挑战状态前置到入口层

**决策类型**: 产品 / 体验

**决策内容**:
1. 首页挑战卡必须直接展示今日挑战状态，而不只展示入口
2. ChallengePage 必须同时承担“个人战绩卡”和“同级别对比”职责
3. 完整榜单继续保留，但不再是用户理解自己位置的唯一入口

- 如果用户必须先完成挑战或深入榜单页才知道自己表现，回访动机会偏后
- 主流产品会把“我的状态”放在入口附近，而不是藏在深层页面
- 个人战绩与同级别位置是不同层次的反馈，应该并列呈现

**状态**: 生效中

### 2026-06-08 - 挑战历史默认围绕“今日当前挑战”

**决策类型**: 产品 / 体验 / 技术

**决策内容**:
1. ChallengePage 的历史回放只展示当前 daily challenge 的当日记录
2. 首页挑战卡的个人最佳提示优先围绕今日挑战样本判断
3. 不把跨天挑战记录混进同一个回放模块里

**决策理由**:
- 用户当前最关心的是“今天这几轮有没有变好”
- 跨天历史会稀释“再来一轮”的即时决策价值
- 先把当日口径打磨清楚，再决定是否扩展到更长时间跨度

**状态**: 生效中

**决策类型**: 产品 / 体验

**决策内容**:
1. 首页挑战卡不仅展示状态，还要明确给出下一步建议

- 统一规则能避免首页与挑战页给出相互矛盾的判断

**决策类型**: 产品 / 体验

- 焦点解释与首页建议复用同一口径，才能避免相互矛盾

### 2026-06-08 - 首页挑战卡需要边界型建议

**决策类型**: 产品 / 体验

**决策内容**:
1. 首页挑战卡不仅要告诉用户什么时候值得继续冲榜，也要告诉用户什么时候该先停下来
2. 当今日挑战样本足够多且表现明显回落时，首页主 CTA 应切回计划训练或自由练习
3. “继续冲榜”和“先收一收”的判断继续复用同一套 challenge strategy state

**决策理由**:
- 主流产品不只给鼓励，也要在用户明显疲劳时给出边界提示
- 如果用户已经掉速还持续冲榜，会稀释产品的教练可信度
- 让首页主 CTA 直接切回训练主线，能减少无效决策

**状态**: 生效中
