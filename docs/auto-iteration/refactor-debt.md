# 技术债记录

## 说明

本文件记录项目中的技术债，包括已知问题和待重构项。

---

## 已知技术债

### 高优先级

#### 1. 缺少代码覆盖率监控
- **问题**: 已有 171 个测试用例，但无覆盖率报告，无法发现测试遗漏
- **影响**: 新增代码可能缺少测试覆盖，无人值守合并时无法验证
- **建议**: 集成 Vitest 覆盖率报告到 CI/CD
- **状态**: 下周规划（主题 A）

#### 2. practice-store.jsx 职责过重
- **问题**: 444 行，包含配置管理、AI 状态、教练状态、历史持久化、UI 联动
- **影响**: 可测试性和可维护性差
- **建议**: 拆分大型 Context，评估状态分离方案
- **状态**: 下周规划（主题 B）

### 中优先级

#### 3. 统一错误处理模式
- **问题**: 错误处理分散在各个模块，缺乏统一模式
- **影响**: 代码可维护性
- **建议**: 提取统一的错误处理中间件或工具函数
- **状态**: 待规划

#### 4. 类型定义补充
- **问题**: 当前代码缺乏类型定义，可维护性有限
- **影响**: 开发体验
- **建议**: 考虑引入 JSDoc 或 TypeScript
- **状态**: 待规划

#### 5. i18n 单文件臃肿
- **问题**: 566 行单文件，中英文文案硬编码，维护成本高
- **影响**: 新增文案容易只改一处导致不同步
- **建议**: 评估分层方案（按页面拆分或按语言拆分目录）
- **状态**: 下周规划（主题 C）

### 低优先级

#### 6. 文档补充
- **问题**: 缺少 API 文档和组件文档
- **影响**: 新开发者上手难度
- **建议**: 添加 JSDoc 和 README
- **状态**: 待规划

## 技术债清理规则

1. 新增功能时，如果发现相关技术债，应先清理技术债
2. 重构时，优先处理高优先级技术债
3. 每次迭代应至少处理一个技术债项
4. 技术债清理后应更新本文件和 decision-log.md
