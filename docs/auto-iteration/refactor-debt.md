# 技术债记录

## 说明

本文件记录项目中的技术债，包括已知问题和待重构项。

---

## 已知技术债

### 高优先级

#### 1. 性能优化：bundle 大小
- **问题**: 当前 bundle 大小约 300KB（gzip: 97KB），首屏加载时间较长
- **影响**: 用户体验
- **建议**: 分析依赖，使用动态导入，压缩图片资源
- **状态**: 待规划

#### 2. 统一错误处理模式
- **问题**: 错误处理分散在各个模块，缺乏统一模式
- **影响**: 代码可维护性
- **建议**: 提取统一的错误处理中间件或工具函数
- **状态**: 待规划

### 中优先级

#### 3. 类型定义补充
- **问题**: 当前代码缺乏类型定义，可维护性有限
- **影响**: 开发体验
- **建议**: 考虑引入 JSDoc 或 TypeScript
- **状态**: 待规划

#### 4. 组件拆分
- **问题**: 部分组件职责过多，如 PracticePage.jsx
- **影响**: 可测试性和可维护性
- **建议**: 拆分大型组件
- **状态**: 待规划

#### 5. AI 服务超时边界情况
- **问题**: AI 服务超时的处理可能不完善
- **影响**: 用户体验
- **建议**: 全面审查超时处理逻辑
- **状态**: 待验证

### 低优先级

#### 6. 文档补充
- **问题**: 缺少 API 文档和组件文档
- **影响**: 新开发者上手难度
- **建议**: 添加 JSDoc 和 README
- **状态**: 待规划

---

## 技术债清理规则

1. 新增功能时，如果发现相关技术债，应先清理技术债
2. 重构时，优先处理高优先级技术债
3. 每次迭代应至少处理一个技术债项
4. 技术债清理后应更新本文件和 decision-log.md
